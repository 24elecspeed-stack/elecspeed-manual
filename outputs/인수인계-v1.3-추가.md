## 2. 작업 종류 — 전기블로그 클립보드 앱 목록으로 교체

신규 파일 `WorkType.java`.

예전에는 `types[]` 하나가 **화면 표시 + 워드프레스 case_type 슬러그**를 겸했습니다(`누전-차단기` 같은 슬러그가 그대로 화면에 보임). 이제 둘로 나눴습니다.

- `WorkType.LABELS` — 화면과 ChatGPT 요청문에 쓰는 사람이 읽는 이름 29개. `references/app-debug-icon.apk`(전기블로그 클립보드)의 `BlogTextGenerator.WORK_TYPES`와 같습니다.
- `WorkType.SLUGS` — 같은 순서의 워드프레스 `case_type` 슬러그.

**중요**: `SLUGS` 값은 전부 예전 `types[]`에 있던 슬러그 중에서만 골랐습니다. 사이트에 없는 슬러그를 새로 만들면 등록할 때 `사이트에서 작업 유형을 찾지 못했습니다: <슬러그>`로 실패합니다. 라벨을 추가할 때는 슬러그도 반드시 사이트에 있는 값으로 짝지어 주세요.

## 4. 화면 디자인 — 전기블로그 클립보드 앱과 같은 모양으로

신규 파일 `Ui.java`.

이 프로젝트는 `build.ps1`이 `aapt package`에 **`-S res`를 안 넘깁니다**. 즉 리소스(styles.xml, drawable xml)를 못 씁니다. 그래서 색·둥근 모서리·그라데이션을 전부 `GradientDrawable`로 코드에서 만듭니다. 디자인을 고칠 때는 XML을 찾지 말고 `Ui.java`를 고치세요.

- 색: 남색 `#16233A`, 노랑 `#FFC629`, 배경 `#F1F4F9`
- 짙은 남색 그라데이션 헤더 + 진행 순서 칩
- 흰 카드 4개 + 노란 원형 번호 배지 (1 카테고리·지역 / 2 글 작성 / 3 가져오기 / 4 미리보기·등록)

**targetSdk 35(Android 15)는 edge-to-edge가 강제**라 그냥 두면 헤더 제목이 상태표시줄에 가립니다. `Ui.header()`가 `setOnApplyWindowInsetsListener`로 상태표시줄 높이를 padding에 더합니다. 헤더를 다시 만들 때 이 부분을 빼먹지 마세요.

## 8. 후속 수정 — "정보성 글 버튼이 안 눌린다" (같은 날)

사용자가 폰에서 버튼이 안 눌린다고 알려왔습니다. 실제로는 **눌리고 있었지만 아무 반응이 없어 보이는 상태**였습니다.

`openWriter()`는 구/시·동이 비어 있으면 `status.setText(...)`만 하고 돌아갑니다. 그런데 `status`는 화면 맨 아래 **4번 카드**에 있고, 버튼은 **2번 카드**에 있습니다. 스크롤 위치상 메시지가 화면 밖이라 사용자는 "안 눌린다"로 느낍니다.

고친 내용:
- `say(String)` 추가 — 메시지를 ①4번 카드 status ②2번 카드 버튼 바로 아래 새 `writeStatus` ③**토스트** 세 곳에 동시에 띄웁니다. 스크롤 위치와 상관없이 반드시 보입니다.
- 성공했을 때도 "정보성 글 요청문을 복사했습니다"를 토스트로 띄웁니다. 예전에는 화면 아래 글자만 바뀌어서 성공했는지도 알기 어려웠습니다.
- `busy`일 때 그냥 `return`하던 것도 "진행 중인 작업이 끝난 뒤에 눌러 주세요"로 알려 줍니다.
- ChatGPT 실행 실패를 `ActivityNotFoundException`만 잡던 것을 `Exception` 전체로 넓혔습니다. 요청문 복사는 그 전에 끝나므로 여기서 실패해도 복사는 남습니다.

검증: 에뮬레이터에서 (1) 지역 비우고 누름 → "1번 카드의 구/시와 동을 먼저 입력해 주세요" 토스트+문구 확인, (2) 지역 채우고 누름 → "정보성 글 요청문을 복사했습니다" 토스트 + ChatGPT(브라우저) 열림 확인.

**폰에서 이래도 아무 메시지가 안 뜨면** 버튼 자체 문제이니 알려 주세요. 그 경우는 원인이 다릅니다.

## 9. 후속 수정 2 — 노란/남색 버튼 오해 + "구동 없이도" 재해석 (같은 날)

사용자 지적 두 가지:
1. "노란색으로 돼야 눌러지는거 아니야?" — 2번 카드 버튼 두 개를 남색/노랑으로 다르게 칠했더니, 사용자가 노란 것만 활성 버튼이라고 오해했습니다. **둘 다 노란색(accent)으로 통일**했습니다.
2. "정보성 글인데 구동을 넣어야해?" — 처음 요청 "구동 없을때도 chatgpt 글쓸수 있게"를 **"출동(방문) 없을 때"로 잘못 읽고** 정보성 글 기능을 만들었습니다. 실제 뜻은 **"구/동(지역 입력) 없이도"** 였습니다.

고친 내용 (정보성 글만 해당, 출장 사례 글은 그대로 지역 필수):
- `ArticleCodec.infoPrompt`에 `regionLine()` 추가 — 구/동이 비어 있으면 "지역: 지정 안 함 — ... 지역명을 절대 넣지 마세요"로, 있으면 기존처럼 "지역: 구 동"으로 씁니다. 제목 지시문도 지역 유무에 따라 분기.
- `openWriter(info)`: `info=true`일 때만 지역 검사를 건너뜁니다. 사례 글(`info=false`)은 여전히 지역 필수.
- `showPreview()`: 지역 필수 검사를 제목·본문만 확인하도록 완화 (지역 없는 정보성 글도 미리보기 가능).
- `template()`/태그 생성부: 지역이 비어 있으면 배너의 지역 줄이 빈 문자열이 되고(빈 div라 자리를 차지 안 함), 앞쪽 지역 기반 해시태그 6개를 건너뜁니다(안 그러면 빈 지역+태그 조합의 이상한 해시태그가 생김).
- SEO 포커스 키워드도 지역 없으면 "전기수리"만 남도록 trim.

검증:
- JVM 신규 테스트(`NoRegionTest.java`, 13개) 전부 통과 — 지역 비움→"지정 안 함" 표기, 지역 있음→정상 지시문 유지, 공백만 넣어도 빈 걸로 처리, 사례 글 동작 불변, 지역 없는 답변도 파싱됨.
- 브라우저로 배너 HTML을 지역 있음/없음 두 버전 렌더링 — 빈 지역 줄이 실제로 자리를 차지하지 않는 것을 눈으로 확인.
- 에뮬레이터: 지역 필드를 비운 채 [정보성 글] 버튼을 눌러도 크래시 없이 정상 진행(ChatGPT 앱이 없어 브라우저로 폴백하는 것까지 확인). 최종(검증 패치 되돌린) APK도 크래시 없음.
