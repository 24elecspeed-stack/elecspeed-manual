## 사용자 요구와 현재 글쓰기 흐름

- 연결 대상은 **ChatGPT**다. Claude로 바꾸지 않는다.
- 출장 사례와 정보성 글 모두 요청문을 복사하고 ChatGPT를 연다. 사용자가 붙여넣어 전송하고 완성 답변을 복사해 앱으로 가져온다. 자동 API 호출 방식이 아니다.
- 검색 후 같은 답변에서 제목·본문·Q&A까지 완성해야 한다. 조사 보고서나 최근 경향만 출력하면 요구 미충족이다.
- 한때 검색→작성 2단계 버튼을 만들었으나 조사에서 멈추는 문제가 있어 v1.9에서 제거했다. 되돌리지 않는다.
- 정보성 글에는 입력된 구·동을 사용하지 않는다. 최근 글 이력도 출장 사례와 분리한다.
- 출장 사례는 실제 현장 메모가 최우선이다. 메모가 있으면 작업 종류 선택값을 제목 근거에서 제외한다. 메모가 없으면 선택 작업을 참고하되 실제 경험을 꾸미지 않는다.
- 제목은 실제 증상과 서비스 문의 의도를 연결하고, 지역만 바꾼 같은 차단기 제목을 반복하지 않는다.

## 최신 소스의 주요 파일

최신 소스 루트 아래 `src/com/elecspeed/manual/`에 있다.

| 파일·함수 | 역할 |
|---|---|
| `MainActivity.java` / `openWriter()` | 실제 입력·이력으로 요청문 생성, 클립보드 복사, ChatGPT 실행 |
| `ArticleCodec.java` / `prompt()`, `infoPrompt()`, `parse()` | 사례·정보성 요청문 및 답변 파싱 |

| `TitleEngine.java` / `plan()`, `serviceCandidates()`, `chooseServiceForPlace()` | 서비스 후보·최근 이력 점수·제목 구조 선택 |
| `WriterStyles.java` | 40개 상세 스타일과 중복 회피 |
| `WorkType.java` | 작업 표시명·워드프레스 taxonomy slug 대응 |

3. 서비스 검색어 후보 확대. 최근 제목·같은 동의 사용 검색어와 최근 그룹에 가중치를 주어 반복을 줄인다. 제목 문법 A~F 순환.

## 검증 범위와 남은 문제

### 완료한 검사

- v1.12 Java 컴파일, APK 제작, v2/v3 서명 검증.
- 정책 테스트 110,783개 assertion 통과. 대부분 1만 회 스타일 선택 반복에서 나온 검사이며 실제 사용자 시나리오 11만 건을 뜻하지 않는다.
- 정보성 요청문의 입력 지역 제거 및 출장 사례 지역 유지.
- 작업 선택이 ‘누전 차단기 내려감’인데 메모가 ‘한쪽 방과 화장실이 전기안됨’인 경우, 조합 요청문에 해당 차단기 증상이 들어가지 않는 회귀 검사.

### 미검증·제한

- 실기기 설치·로그인·클립보드·ChatGPT 실제 응답·워드프레스 등록 E2E는 미검증이다. 마지막 ADB 조회에서 연결 기기가 없었다.
- 프롬프트 검사 통과는 실제 AI가 검색하고 완성 글을 쓴다는 보장이 아니다. 사용자에게 같은 문제가 반복 보고되었으므로 반드시 실제 복사 요청문과 응답을 확보한다.
- 문체 이력은 요청 생성 시 기록한다. 실제 완성 글 구조를 앱이 분석해 자동 재선택하는 기능은 아니다.
- 같은 동 중복 검사는 로컬 최근 제목 범위다. 웹사이트 전체 글을 자동 조회하는 기능이 아니다.
- 키워드 판정은 문자열 기반이다. 부정문·복합 증상·선택 작업과 메모 충돌은 추가 실사용 검증이 필요하다.
- 정보성 글은 선택 작업을 주제로 사용한다. 사용자가 작업 선택을 바꾸지 않으면 주제가 반복될 수 있다.
- 기존 게시글 HTML의 고정 태그에는 여러 고장명과 24시간·긴급 표현이 남아 있다. 제목 요청문 수정과 별개이며 이번 변경에서 건드리지 않았다.
- `case_type` 존재를 요구하는 기존 업로드 코드, ACF/Yoast/대표이미지 저장 결과는 실제 서버에서 확인해야 한다.
