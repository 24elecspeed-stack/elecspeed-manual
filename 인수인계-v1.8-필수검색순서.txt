# elecspeed-manual — 필수 웹검색 순서 개편 인수인계 (2026-09-15, v1.7 다음)

v1.7 다음에 이어지는 내용입니다. **이번 건은 elecspeed-manual(이 폴더)만 해당합니다.**
ElectricBlogClipboard(네이버 블로그 앱)는 이번 작업에서 건드리지 않았습니다 — v1.7의 "6. 오늘 있었던 혼동"과
같은 실수를 반복하지 않으려고 사용자가 "블로그앱 아니야, elecspeed-manual 이거야"라고 먼저 못박았습니다.

## 1. 문제 상황

ChatGPT/Claude가 프롬프트에서 "검색해서 조사한 뒤 쓰라"는 지시를 실제로 건너뛰는 경우가 많았음.
사용자 진단: 프롬프트 안에 경쟁하는 지시가 너무 많으면(제목 규칙, 분량, 출력 형식 등) 모델이 뒤쪽/출력-형식에
가까운 지시를 우선하고, 앞쪽의 절차적 지시("검색부터 해라")는 밀려남. 게다가 기존 문구가
"검색할 수 있으면 위 조건으로 먼저 조사한 뒤 글을 쓰세요"처럼 **소프트(선택적) 표현**이었던 것도 원인으로 지목됨.

## 2. 적용한 해결 방식

### `WritingCategory.java` — `researchPrompt()`
기존: 검색 키워드/최신성/우선순위/톤을 나열한 뒤 마지막 한 줄로 "검색할 수 있으면...검색했다고 표현하지 마세요."
변경: **`[필수 실행 순서 — 절대 생략 금지]`** 섹션으로 전면 재작성. 7단계 번호 절차:
1. 웹 검색 도구를 사용할 수 있는 경우 반드시 검색한다(검색 도구가 실제로 없는 환경에서만 생략).
2. 카테고리 검색 키워드 중심으로 최신성 기준 자료를 먼저 찾는다(키워드는 참고 자료일 뿐이라는 단서 유지).
3. 우선순위 검색 채널(네이버/구글, 블로그/뉴스/웹 전체) + 제조사·공공기관·전문가 자료도 함께 확인.
4. 블로그 글의 기술적·안전 주장은 공식 자료와 대조.
5. 최근 비슷한 글들의 제목·구성 경향 확인.
6. "최근 가져온 제목" 목록과 비교해 반복 피하기.
7. 위 과정을 모두 마친 뒤에만 글 작성.

추가로 **검색을 실제로 안 했으면 검색했다고 표현 금지**, **완성된 글 끝에 검색 결과·출처 목록을 따로 붙이지 말 것**(참고만 하고 본문에 자연스럽게 녹이기)을 명시적으로 금지 문구로 추가.

### `ArticleCodec.java`
- `RESEARCH_MARKER` 상수(`"[사전 조사 자리표시자]"`) 추가 — `prompt()`/`infoPrompt()` 둘 다 **요청문 맨 앞**(제목/작업정보보다도 먼저)에 이 마커를 심어 둠.
- `prompt()`(출장 사례 글) 섹션 순서를 재배열: **필수 웹검색 → 지역/작업종류/현장메모 → 주제 결정 규칙 → 제목 작성 지침 → 최근 가져온 제목 → 본문 작성 기준/전개/문체 → 출력 형식**.
  (예전에는 필수 검색 지시가 `[작성 기준]` 바로 앞, 즉 프롬프트 중간에 끼워져 있었고, 제목 지침이 본문 규칙 *뒤*에 있었음.)

### `MainActivity.java` (`openWriter()`)
- 기존: `.replace("[작성 기준]", c.researchPrompt()+"\n[작성 기준]")` — 카테고리 검색 지침을 본문 규칙 앞에 끼워 넣는 방식.
- 변경: `.replace(ArticleCodec.RESEARCH_MARKER, c.researchPrompt())` — `ArticleCodec`이 이미 맨 앞에 심어둔 마커를 그대로 치환. 결과적으로 필수 검색 절차가 요청문의 첫 섹션이 됨.

## 3. 확인한 것 / 못 한 것

확인함: `work/android/build.ps1` 클린 빌드 성공, `outputs/elecspeed-chatgpt.apk` 전달, 코드 상에서
필수 검색 섹션이 프롬프트 최상단에 오도록 문자열 조립 순서 직접 대조.

못 함: 실제로 ChatGPT/Claude 앱에 이 요청문을 붙여넣어서 검색을 실제로 수행하는지 실기기 확인. 이건
프롬프트 문구만으로는 100% 보장할 수 없는 영역이라 실사용 중 계속 관찰이 필요함.

## 4. 아직 안 한 것 — v1.7에서 넘어온 미완료 항목 (이번 건과 무관, 여전히 대기 중)

v1.7 문서의 "4. elecspeed-manual — 부분 완료" 항목이 **아직 그대로 미완료**임:

1. **4개 카테고리 개편** — 기존 4개 카테고리를 "정전·부분정전·전기안됨 / 누전·배선·절연 이상 /
   차단기·분전반·과열·화재징후 / 콘센트·가전·전열·생활전기 고장"으로 통째로 교체. 전체 스펙은
   v1.7 문서의 "카테고리 1~4"와 "구현 시 주의할 점" 참고 (새 id 필요, `WorkType.defaultIndexFor` 재매핑 필요).
2. **작성자 스타일 다양화** — 40개 페르소나(여성 20+남성 20)에 13개 속성(도입방식/문장 길이/질문 빈도/
   전문용어 정도 등)을 부여하고, 이전 글과 8개 구조 항목 중 3개 이상 겹치면 재선택하도록 하는 로직.
   본문 전개도 기존 8종(A~H)에서 **10종(A~J)**으로 확장, 9개 문구 회피 목록, 8종 소제목 유형(최근 5편 회피),
   "이전 글의 템플릿 교체가 아님"을 확인하는 최종 자체 점검 섹션까지 포함. 이 스펙은 대화 중 사용자가
   길게 붙여넣은 "[작성자 스타일 다양화 — 필수]" 원문을 그대로 따라야 함(이 문서에는 요약만 있음 —
   원문이 필요하면 세션 대화 기록 참고). `TitleEngine.java`의 `BodyFlow`/`FEMALE_PERSONAS`/`MALE_PERSONAS`를
   손봐야 함.

사용자가 "이렇게 apk 만들어 같이 위에 꺼랑 같이 만들어줘"라고 이 두 가지를 함께 요구했었는데,
그 직후 "필수 검색 순서" 요청이 더 급하게 들어와서 이번 빌드는 검색 순서 개편만 반영했습니다.
**다음 세션(또는 이어서)에서 위 1, 2번을 마저 구현해야 합니다.**
